# airdrop-agent

Личный инструмент для одного пользователя. Telegram-юзербот читает ваши крипто-чаты, Claude
классифицирует каждый пост (ищем testnet, программы с поинтами, airdrop и т. п.), новые
возможности приходят карточкой от Telegram-бота с кнопками «Беру / Мимо», решения
записываются в SQLite.

Этап 1 только читает: никаких кошельков, транзакций и автоматических действий.

## Как это работает

1. Юзербот (Telethon) подтягивает последние `BACKFILL_LIMIT` сообщений из каждого отслеживаемого
   чата и подписывается на новые. Отслеживаются чаты из папки `WATCH_FOLDER` и из `WATCH_CHATS`.
2. Посты обрабатываются строго по очереди, чтобы запросы к Claude не шли пачкой.
3. Claude возвращает структурированную классификацию. Шум отбрасывается.
4. Проект определяется по ключу (домен, иначе название). Повторное упоминание того же проекта
   не создаёт новую карточку, а только увеличивает счётчик упоминаний.
5. Домен от модели принимается, только если такая ссылка реально есть в посте. В карточке
   показываются только ссылки из самого поста.
6. Перед карточкой нового проекта с доменом выполняется бесплатная проверка (см. ниже).
7. Бот присылает карточку владельцу; нажатие «Беру» или «Мимо» фиксируется в базе.
   Команда `/stats` показывает счётчики по статусам и типам.

## Настройка

1. `api_id` и `api_hash`: https://my.telegram.org, раздел API development tools.
2. Токен бота: создайте бота у @BotFather.
3. Свой user id: напишите @userinfobot.
4. Ключ Anthropic: https://console.anthropic.com, ключ идёт в `ANTHROPIC_API_KEY`.
5. Что отслеживать: заполните `WATCH_FOLDER`, `WATCH_CHATS` или оба (нужно хотя бы одно,
   иначе `run` не запустится; итоговый набор чатов это объединение без повторов).
   - `WATCH_FOLDER`: название папки Telegram с вашими крипто-чатами. Регистр и пробелы по
     краям не важны. Точное название можно посмотреть командой `folders` (см. ниже).
   - `WATCH_CHATS`: через запятую юзернеймы (`some_chat`) или числовые id (`-1001234567890`).
   - `WATCH_EXCLUDE` (необязательно): через запятую чаты, которые нужно убрать из итогового
     набора (мёртвые, чисто новостные, боты). Подходит числовой id (`-1001234567890` или без
     `-100`), юзернейм (регистр и `@` не важны) или название чата (регистр и пробелы по краям
     не важны). Пример: `WATCH_EXCLUDE=Some News,somebot`. Исключённые чаты пишутся в лог;
     запись, которая ничему не соответствует, даёт WARNING (не ошибку).
   - `MAX_POST_AGE_DAYS` (по умолчанию 14, `0` = без ограничения): сообщения старше лимита
     не сохраняются в `collect` и не обрабатываются в `run`. Уже сохранённые посты `new`/`retry`
     старше лимита не классифицируются ни в `classify-pending`, ни в цикле повторов: они
     остаются в базе со своим статусом, а `classify-pending` пишет, сколько пропущено.
   Ваш аккаунт должен состоять в этих чатах.
6. Напишите своему боту `/start`, иначе он не сможет написать вам первым.

```
cp .env.example .env   # и заполните значения
uv sync
uv run python -m airdrop_agent login   # один раз: телефон, код, пароль 2FA
uv run python -m airdrop_agent folders   # папки и чаты в них: проверить название для WATCH_FOLDER
uv run python -m airdrop_agent run
```

## Команды

- `login`: один раз авторизует юзербота. Нужны только `TG_API_ID` и `TG_API_HASH`.
- `folders`: показывает папки Telegram и чаты в них.
- `collect`: только собирает посты (подтягивает историю и слушает новые) и складывает в базу
  со статусом `new`. Claude и бот не запускаются, `BOT_TOKEN`, `OWNER_USER_ID` и
  `ANTHROPIC_API_KEY` не нужны. В лог на каждый сохранённый пост пишется строка
  (чат и id сообщения), а каждые 25 новых постов ещё и общий счётчик.
- `classify-pending [N]`: берёт до N (по умолчанию 20) сохранённых постов со статусом `new`,
  самых старых первыми, прогоняет через обычный пайплайн (классификация и карточки через бота)
  и завершается. В конце печатает сводку: обработано, классифицировано (из них шум), failed,
  retry, ошибок и отправлено карточек. Временная ошибка (лимит, сеть) останавливает проход:
  пост уходит в `retry`, остальные остаются `new`.
- `run`: полный режим: сбор, классификация, бот, повтор постов из `retry`.

## Проверка проекта

Для **нового** проекта (повторные упоминания не проверяются) перед отправкой карточки
проверяются бесплатные внешние источники, Claude тут не участвует:

- Фишинг-базы ScamSniffer и MetaMask (чёрные списки; белый список MetaMask отменяет
  срабатывание, fuzzylist игнорируется). Сверяются домен и его родительские домены.
  Списки скачиваются в `data/cache/` и обновляются раз в сутки; если обновление не удалось,
  используется старая копия.
- Возраст домена по RDAP (`rdap.org`) для основного домена. Результат кэшируется в базе
  на 7 дней. Домен младше 90 дней помечается ⚠️.
- DeFiLlama (`api.llama.fi/protocols`): название, категория, TVL, аудиты, дата листинга.
  Каталог обновляется раз в сутки. Отсутствие в DeFiLlama само по себе не тревожный признак:
  тестнеты до запуска там обычно не числятся.

Результаты выводятся в блоке «Проверка» на карточке. Источник, который не ответил за 10 секунд
или упал, не блокирует карточку: в строке будет «не удалось проверить». Если домен не указан,
карточка пишет «сайт не указан, проверить нельзя».

**Заблокированные проекты.** Если домен найден в фишинг-базе, карточка не отправляется и
возможность не создаётся. Запись попадает в таблицу `blocked_projects` (ключ проекта, домен,
списки, ссылка на пост, время) и в лог с уровнем WARNING.

Отключить проверку: `ENRICH=false` в `.env` (по умолчанию включена).

### Рекомендуемый порядок

1. Пока на счету Anthropic нет денег: `collect` оставляйте работать, посты копятся в базе.
2. Когда баланс пополнен: `classify-pending 20`, чтобы проверить качество классификации
   и стоимость на небольшой пачке.
3. Дальше `run`. Посты со статусом `new` считаются необработанными, поэтому `run` сам
   классифицирует собранные ранее посты, которые попадают в окно истории (`BACKFILL_LIMIT`
   последних сообщений каждого чата). Более старые остаются в базе: их разбирает
   `classify-pending N`.

### Ограничения папок

Из папки берутся чаты, которые добавлены в неё явно (включённые и закреплённые). Исключения
папки (`exclude_peers`) и категории («все каналы», «непрочитанные» и т. п.) не поддерживаются.
Папка, заданная только категориями, отклоняется с сообщением об этом: добавьте в неё чаты
вручную или перечислите их в `WATCH_CHATS`. Состав папки читается при запуске `run`;
после изменения папки перезапустите бота.

## Предупреждение о безопасности

Файл сессии (`data/user.session`) даёт полный доступ к вашему Telegram-аккаунту. Никому его
не передавайте и не коммитьте. `.env` и `data/` уже в `.gitignore`.
