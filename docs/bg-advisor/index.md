# bg-advisor

Советчик для Hearthstone Battlegrounds. Шаг 1: читает `Power.log` и хранит состояние сущностей игры (карты, герои, теги, ходы). Шаг 2: проекция состояния Battlegrounds (золото, таверна, стол, рука, таблица лидеров) и русские названия карт. Шаг 3: запоминает столы соперников, виденные в боях, и в найме прогнозирует бой со следующим соперником симулятором Firestone. Шаг 4: совет — какое одно действие сильнее всего повышает шансы в бою.

## Запуск

```
npm install
npm run dump -- <путь к Power.log>   # разобрать готовый лог, по строке на игру
npm run watch                         # следить за живым логом (новая игра, смена хода)
npm run cards                         # скачать русские названия карт в data/cards.json
npm run bg-dump -- <путь к Power.log> # снимок BG и прогноз боя на каждом этапе найма, в конце таблица «прогноз против факта»
npm test
npm run typecheck
```

В игре Battlegrounds `watch` печатает снимок в начале найма и перепечатывает его после изменений (покупка, продажа, обновление; задержка 300 мс). Без `data/cards.json` вместо названий выводятся cardId.

`watch` читает самую новую папку `Hearthstone_<дата>` в `/Applications/Hearthstone/Logs` с начала файла и дальше следит за дописываемыми строками. Другой корень логов можно передать аргументом: `npm run watch -- <папка>`.

## Логи

Логи лежат в `/Applications/Hearthstone/Logs/Hearthstone_<дата>/Power.log`. Чтобы они писались, в `~/Library/Preferences/Blizzard/Hearthstone/log.config` должна быть включена секция `[Power]` (на этой машине уже включена).

Разбираются только строки `GameState.DebugPrintPower()` и `GameState.DebugPrintGame()`; `PowerTaskList.*` дублирует их и игнорируется.

## Устройство

- `src/log/` — `parseLine` (строка → `PowerEvent`), `follow` (чтение и слежение за файлом).
- `src/state/gameState.ts` — хранилище сущностей, принимает `PowerEvent`.
- `src/bg/` — `buildSnapshot` (сущности → `BgSnapshot`, за один проход), `render` (снимок → текст), `fromState` (ids из `GameState`).
- `src/bg/combatTracker.ts` — конечный автомат найм → бой → найм; в первой атаке боя запоминает стол соперника (`playerId` → последний виденный стол).
- `src/bg/forecast.ts` — прогноз боя со следующим соперником по его последнему виденному столу; симулятор подключается через собственный узкий интерфейс `BattleSimulator`.
- `src/advisor/` — совет: `actions` (перебор действий), `opponents` (какие столы и с каким весом), `evaluate` (оценка симулятором через тот же `BattleSimulator`, отсечение, топ-3).
- `src/sim/` — `battleInput` (наши типы → вход симулятора Firestone), `simulator` (сам симулятор).
- `src/cards/cardDb.ts` — названия карт из `data/cards.json`; `scripts/fetch-cards.ts` его скачивает.
- `src/cli/` — `dump`, `bgDump`, `watch`; `report` — общий путь «снимок + прогноз → текст» для двух последних.

## Прогноз боя

Симулятор — `@firestone-hs/simulate-bgs-battle` (версия зафиксирована). Его лицензия «All rights reserved», поэтому он используется только для личных нужд и не распространяется.

Базу карт симулятор скачивает с `static.zerotoheroes.com` при первом запуске и кэширует в `data/firestone-cards.json` (в `.gitignore`); чтобы обновить, удалите файл.

Известные неточности:

- Стол соперника снимается в первой атаке боя, к этому моменту уже сработали эффекты начала боя.
- Прогноз строится по последнему виденному столу этого соперника; он мог вырасти с тех пор (соперник попадается раз в несколько ходов). Здоровье и уровень соперника берутся из таблицы лидеров на момент найма.
- Золотые миньоны в логе идут со своим cardId (`…_G`) и `PREMIUM=1`, отдельного преобразования не нужно.
- Аксессуарам симулятор передаётся только cardId, их счётчики (`scriptDataNum`) не учитываются.
- Свои эффекты, накопленные за игру (глобальные бонусы, награды квестов), симулятору не передаются.

## Совет

В найме после прогноза печатается до трёх действий с наибольшим выигрышем: купить миньона из таверны (золото ≥ 3, стол < 7), при полном столе — продать своего и купить (золото + 1 ≥ 3), выставить миньона из руки. Новый миньон всегда ставится в конец стола. При продаже перебираются только три самых слабых своих миньона по атаке + здоровью, золотые не продаются.

Оценка — перевес «победа − поражение» в процентах: 1000 симуляций на стол соперника для текущего стола и 300 для каждого кандидата. Считается по всем виденным столам живых игроков (есть в таблице лидеров), взвешенно: вес стола вдвое меньше за каждые 6 ходов давности, стол следующего соперника весит ещё вдвое больше. Итог — Σ вес × (победа − поражение) / Σ вес. Если столов нет — эвристика, сумма атаки и здоровья стола.

Действия с выигрышем ≤ 0 отбрасываются; если не осталось ни одного, печатается «ничего из таверны не усиливает стол» (а «ходов нет» — когда действий не было вовсе). Прогноз боя выше отвечает на другой вопрос — про следующий бой — и от весов не зависит.

Известные ограничения:

- Боевые кличи, заклинания таверны, расстановка, повышение уровня, обновление и заморозка не оцениваются.
- Позиция нового миньона не выбирается, он всегда в конце.
- Устаревший стол соперника (он мог вырасти) искажает результат, хотя его вес и падает со временем.
- На поздних ходах с сильными столами симуляция идёт заметно дольше секунды на снимок.
