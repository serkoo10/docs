# Дизайн-система

Как выглядит приложение и почему. Код темы живёт в `app/lib/core/theme`, этот документ —
решения, которые из кода не прочитать.

## 1. Зачем менялась тема

Исходная тема (до 2026-10-06) — одна строка: `ColorScheme.fromSeed(seedColor: #FC4C02)`.
Проблемы:

- `#FC4C02` — фирменный оранжевый Strava один в один. Чужая узнаваемость и риск при ревью.
- `fromSeed` не даёт бренд-цвет в интерфейс: primary выходит тёмно-ржавым (тон 40),
  `primaryContainer` лососевым, `secondaryContainer` бежево-розовым, поверхности с тёплым
  подкрасом. Много тёплых пастелей, конкурирующих друг с другом — глаз устаёт.
- Статусы (запланирована, выполнена, в эфире, пропущена) красились теми же пастелями:
  цвет не нёс смысла.
- Material-дефолты: чипы и инпуты с обводкой, карточки с тональной тенью. На iOS выглядит
  чужим.
- Нет тёмной темы.

Что было хорошо и сохранено: ни одного цвета вне темы, все виджеты берут цвета из
`colorScheme`, размеры из `textTheme`, отступы из `AppSpacing`. Поэтому смена
визуала — правка модуля темы, а не проход по фичам.

## 2. Конкуренты

| Приложение | Визуал | Слабое место |
|---|---|---|
| Strava | Плоский стиль, острые углы 0–4 px, оранжевый `#FC5200` как акцент, жёлтый KOM, серые нейтрали | Главная — соцлента, а не личные данные; иконки без подписей (настройки, карта, обувь); функции под пейволом выглядят как доступные; хаос после отмены хронологической ленты |
| Nike Run Club | Белый фон, чёрный текст, лёгкая типографика, много воздуха, один неоновый акцент только на действиях; эмоцию несёт фотография | Монохром без семантики: уровень и темп кодируются цветом, но статусы тренировок — нет; без фотографии экран пустой |
| adidas Running | Крупная кнопка «Старт», живые метрики | Абстрактные иконки видов активности без подписей; скрытые жесты (свайп для паузы, свайп по карте открывает настройки); маленькая кнопка назад |
| Garmin Connect (редизайн 2024) | Крупные карточки-плитки | Плотность данных упала: «огромные плитки, пустое место, больше скролла и кликов»; пользователи массово просили старую версию |
| Runna | Недельная полоса сверху, прогресс-шкала, цветовое кодирование типов пробежек | Оценка дизайна 4/5; всё построено вокруг плана, клубов и тренера как человека нет |
| Polar Flow / COROS | Чистые графики, тёмная тема у Polar | Приложения для часов: без тренера, клуба, календаря |
| Pacelo (РФ) | Клубы, расписание, QR-посещаемость, недельные планы, ИИ-разбор | Молодое приложение (до 1 000 установок), визуально обычное «спортивное» |
| SIMPLA (РФ) | Трекер, соцсеть, планы, метроном | Трекер-центричное, тренера нет |

Выводы для нас:

1. Один акцент, редко. Все сильные (Nike, Apple) держат базу нейтральной и красят только
   действия. Пастельные заливки везде — наша исходная ошибка.
2. Семантика статусов — отдельный слой цветов. Ни у кого из конкурентов «запланировано /
   выполнено / отменено» не читается цветом с первого взгляда.
3. Плотность важнее «воздуха». Урок Garmin: тренер смотрит список атлетов и неделю, ему
   нужен компактный список, а не плитки.
4. Иконка всегда с подписью. Общая боль Strava и adidas.
5. Тёмная тема нужна с первого дня: бег вечером, экран в руке.

## 3. Принципы (в духе Apple HIG)

- Нейтральная база: сгруппированный фон `systemGroupedBackground`, белые/графитовые
  ячейки-карточки без тени, разделители вместо обводок.
- Один акцентный цвет — только интерактив: кнопки, ссылки, активная вкладка, фокус.
  Неинтерактивное акцентом не красится.
- Семантические цвета статусов фиксированы и не зависят от акцента: синий — впереди,
  зелёный — выполнено / в эфире, серый — прошло / пропущено, красный — отменено / ошибка.
- Форма: радиус 12 у карточек, кнопок и полей, пилюля у чипов, минимальная высота
  кнопки 50 (≥ 44 по HIG).
- Типографика системная (SF на iOS, Roboto на Android), заголовки плотнее
  (вес 700, трекинг −0,5), подписи 600. Размеры Material не меняем — вёрстка не плывёт.
- Цифры табличные во всех стилях текста, не только в метриках: число есть почти в каждой
  строке, и столбцы темпа, времени и счётчиков не дрожат при смене знаков. Цена — чуть
  более широкая «1» в прозе, принято.
- Число и единица (или счётное слово) разделены неразрывным пробелом в arb: «8,5 км»,
  «3 участника» не рвутся по строке.
- Нажатие — заливка ячейки `fillStrong` без волны Material (`NoSplash`), как в iOS. Кнопки
  сохраняют свой overlay на pressed.
- Tinted-контрол один на всех: `accentContainer` под текстом цвета `accent`. Так выглядят
  `OutlinedButton`, выбранный чип и выбранный сегмент `SegmentedButton`; дорожка сегментов —
  `fill`, без контура и разделителей.
- `ListTile` с полями 16 с обеих сторон (M3 даёт 24 справа): правый край строки сходится с
  краем карточек и кнопок AppBar.
- Ошибка под любым полем — один стиль `errorStyle` темы (`bodySmall` + `danger`):
  `TextFormField` берёт его сам, самодельные поля через `FieldError`.
- Статус-чип один — `StatusChip` с парой из `AppStatusColors`; фичи оставляют себе только
  `switch` по статусу.
- Иконки контурные по умолчанию. Заливка только для состояния «включено» (выбранная вкладка,
  тумблеры микрофона и камеры, play/pause/stop, точка записи) и для лиц медалей. У глифов без
  тела (`add`, `check`, `chevron`, `block`, `logout`) варианты совпадают, их не трогаем.
- Тактильный отклик по смыслу, сила выбирается в `core/haptics.dart`: `select` на сегменте и
  чипе, `success` на удачном `runAction` и `runSubmit`, `celebrate` на новой медали. На
  подтверждении удаления и pull-to-refresh отклика нет, iOS там тоже молчит.
- На изумруде текст `onEmerald` (белый / чёрный): `onTertiary` темы и `onAccent` варианта
  «Изумруд» берут его из одного места.
- Просмотр фото всегда чёрный с белыми кнопками в обеих темах: пара из `AppViewerColors`,
  чужие роли схемы (`scrim`, `onError`) для этого не занимаем.
- Сплэш не молчит: через две секунды под спиннером «Подключаемся к серверу…», а если сервер
  не ответил — «Нет связи с сервером» и «Повторить». Сессия при этом не сбрасывается
  (состояние `offline`): человек с живым токеном не должен попадать на ввод телефона из-за
  спящего сервера.
- Пустой список — `EmptyState`: контурная иконка смысла экрана, заголовок, подсказка и
  действие, когда оно есть. На пустом экране FAB прячется, действие остаётся одно.
  Иллюстраций нет: для них нужен дизайнер, иконка закрывает пустоту до тех пор.
- Загрузка главных списков — скелетон той же формы, что карточка, с общей пульсацией
  (`SkeletonPulse`); остальные экраны — спиннер. При «уменьшить движение» плашки не пульсируют.
- Индикаторы `.adaptive`: на iOS спиннер и pull-to-refresh Cupertino, на Android Material.
- Фото открываются на весь экран: свайп между фото, зум щипком, закрытие свайпом вниз; Hero
  от карусели и сетки поста. Hero от карточки списка до экрана объявления не сделан: экран
  грузит объявление сам, фото там нет до ответа.
- Низ списка — `AppSpacing.m`, под плавающей кнопкой `AppSpacing.fabClearance`.
- Там, где над списком поле ввода (чат, поиск страны, фильтры), клавиатура прячется при
  прокрутке.
- Контраст: текст на акценте ≥ 3:1 (жирный, ≥ 16 pt), основной текст ≥ 4.5:1.

## 4. Токены

Нейтрали и семантика общие для всех вариантов (значения системных цветов iOS):

| Токен | Светлая | Тёмная | Где |
|---|---|---|---|
| background | `#F2F2F7` | `#000000` | Scaffold, AppBar |
| surface | `#FFFFFF` | `#1C1C1E` | Card, инпут, NavigationBar, диалог, лист |
| fill | `#E5E5EA` | `#2C2C2E` | чип по умолчанию, плейсхолдер фото, чужое сообщение |
| fillStrong | `#D1D1D6` | `#3A3A3C` | нажатие, индикатор выбора |
| label | `#000000` | `#FFFFFF` | основной текст |
| secondaryLabel | `#8A8A8E` | `#98989F` | подписи, вторичный текст, неактивные вкладки |
| tertiaryLabel | `#AEAEB2` | `#636366` | плейсхолдеры |
| separator | `#C6C6C8` | `#38383A` | Divider, граница чипа-выбора |
| success | `#34C759` | `#30D158` | выполнено, в эфире, «иду» |
| info | `#007AFF` | `#0A84FF` | запланировано, забронировано |
| warning | `#FF9500` | `#FF9F0A` | медали забегов |
| emerald | `#059669` | `#34D399` | медали рекордов, акцент варианта «Изумруд» |
| indigo | `#5856D6` | `#5E5CE6` | медали пробежек |
| danger | `#FF3B30` | `#FF453A` | отмена, удаление, ошибка |

Контейнер статуса — его цвет с альфой 0.15 на фоне, текст — сам цвет. В тёмной теме та
же формула.

Варианты различаются только акцентом. Три варианта, переключаются в профиле:

| Вариант | accent светлая / onAccent | accent тёмная / onAccent | Характер |
|---|---|---|---|
| Графит | `#1C1C1E` / `#FFFFFF` | `#F2F2F7` / `#000000` | монохром как у Nike, цвет остаётся только статусам |
| Изумруд | `#059669` / `#FFFFFF` | `#34D399` / `#000000` | свежий беговой зелёный; статус «выполнено» зелёный тоже, но другого тона |
| Океан | `#007AFF` / `#FFFFFF` | `#0A84FF` / `#FFFFFF` | классический iOS; статус «запланировано» совпадает с акцентом — это осознанно, так у Apple |

`accentContainer` = accent с альфой 0.15 (своё сообщение в чате, tinted-кнопка,
выбранный чип).

## 5. Архитектура темы

```
app/lib/core/theme/
  app_spacing.dart           отступы (было)
  app_radius.dart            радиусы: s 8, m 12, l 16
  app_palette.dart           AppPalette — все токены выше + brightness; без логики
  palettes/
    neutral_palette.dart     нейтрали и семантика, light/dark
    graphite_palette.dart    акцент варианта → AppPalette.light / .dark
    emerald_palette.dart
    ocean_palette.dart
  app_theme_variant.dart     enum AppThemeVariant { graphite, emerald, ocean }
  app_status_colors.dart     ThemeExtension: info/success/neutral/danger → (background, foreground)
  app_theme.dart             buildAppTheme(AppPalette) → ThemeData
  theme_settings.dart        ThemeSettings(variant, mode) — значение
  theme_settings_storage.dart интерфейс + реализация на shared_preferences
  theme_settings_notifier.dart Riverpod Notifier, читает/пишет storage
```

- `ColorScheme` собирается вручную из палитры, `surfaceTint` прозрачный:
  primary = accent, primaryContainer = accentContainer, secondaryContainer = fill,
  tertiaryContainer = warning-контейнер, surface/onSurface = surface/label,
  onSurfaceVariant = secondaryLabel, outline = separator, surfaceContainerHighest = fill,
  error = danger. Так существующие обращения к `colorScheme` остаются верными.
- Статусные чипы берут цвета из `AppStatusColors`, а не из контейнеров `colorScheme`:
  контейнеры — про акцент, статус — про смысл.
- `MaterialApp.router`: `theme` = светлая палитра варианта, `darkTheme` = тёмная,
  `themeMode` из настроек. Переключение — мгновенное, без перезапуска.
- Выбор хранится в shared_preferences; читается до `runApp`, провайдер
  переопределяется в `ProviderScope`.

## 6. Переключатель

Профиль → раздел «Оформление»: три `SegmentedButton` — вариант (Графит / Изумруд /
Океан), режим (Системная / Светлая / Тёмная) и форма медали (Номер / Нашивка /
Плитка, по умолчанию нашивка). Раздел остаётся в релизе как
пользовательская настройка; если после выбора варианты сократят до одного, уберётся
только первый переключатель.

## 7. Что решено и что открыто

Решено: нейтральная база, фиксированная семантика статусов, три кандидата акцента,
системная типографика.

Открыто: какой вариант акцента станет единственным — решается глазами на устройстве
после сравнения. Иллюстрации и фото как эмоциональный слой (как у Nike) — отдельная
задача, тема к ней готова.

## 8. Достижения

- Коллекция медалей в духе Nike Run Club: фиксированный набор по лестницам из enum
  (`achievement_ladders.dart`: пробежки, километры, рекорды). Полученная медаль цветная,
  неполученная серая с пониженной непрозрачностью. VoiceOver читает медаль в лестнице как
  «название, дата» или «Медаль ещё не получена»; медали рядом с видимым заголовком декоративные.
- Повторяемые виды (забег, своё, неизвестный) в лестницы не входят и остаются
  хронологическим журналом под коллекцией.
- Медаль — один виджет `AchievementMedal` (размеры 40–160); число или иконка на ней
  задаёт `medalFace`. Тап по полученной открывает экран деталей.
- Цвет по семейству из расширения `AppMedalColors`, фиксирован и не зависит от акцента:
  пробежки — индиго, километры — `info`, рекорды — изумруд, забег — `warning` (золото),
  своё и неизвестное — `secondaryLabel`. Неполученная — `outline`. Форму медали (номер / нашивка / плитка) выбирает
  пользователь в «Оформлении».
- Число на цветной медали чёрное или белое по яркости цвета семейства
  (`AppMedalColors.onMedal`): в тёмной теме семейства светлее, и белое на зелёном и
  оранжевом не читалось. Номер не затронут: там чернила на бумаге.
- Публичный профиль одноклубника показывает ту же коллекцию (`AchievementCollectionView`),
  но без открытия деталей: меню и «Поделиться» только для своих.
- В лестнице у вида одно достижение, новейшее: улучшенный рекорд заменяет старый.
- Открыто: прогресс до следующей медали («37 из 50 км») — отдельная задача, нужен
  счётчик от бэкенда.
