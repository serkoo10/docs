# Замер производительности, 2026-10-13, сравнение с базовой линией

## Окружение

То же, что в `2026-10-04-baseline.md`: MacBook Pro (Apple Silicon), API и k6 на хосте, Postgres 16 в
Docker, сеть localhost. Данные `backend/cmd/seed` с теми же объёмами, `-rng-seed 1`, в отдельной базе
`runclub_load` (dev-база не трогалась); API на `:8081`, Redis DB 1. Коммит `7aab233` плюс незакоммиченные
правки дня (UTC в метках времени, лимиты OTP для тестового номера). Сценарии по 60 секунд.

База сравнения — прогон 2026-10-04 после улучшений того же дня.

`SummarizeDoneWorkouts`, `BestDurationsByBand`). Метод записан в `backend/load/README.md`.

## Выводы

- Все пороги выдержаны, регрессий относительно базовой линии нет: латентности на 10–50 % ниже, CPU Postgres при
  опросе диалогов 9.7 % против 12.8 %. Разница в пределах разброса ноутбука, улучшений в горячих запросах
  между прогонами не было; главное, что ничего не просело.
- Импорт остался на 170 мс при пороге 1 с, узкое место в нём не база (2 запроса на элемент), а сам объём пачки.
- Слабые места по росту из `docs/testing.md` остаются теми же: подстрочный поиск и фасет брендов по объявлениям,
  коррелированные счётчики. При объёмах первого года не проявляются.
